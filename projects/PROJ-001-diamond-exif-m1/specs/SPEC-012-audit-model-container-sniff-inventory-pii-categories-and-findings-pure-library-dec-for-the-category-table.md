# SPEC-012: Audit model: container sniff, inventory, PII categories and findings (pure library); DEC for the category table

> **OUTLINE — `cycle: frame`.** This spec exists so its ID is stable and
> siblings can declare `depends_on: [SPEC-012]`. Capture **scope** (Context /
> Goal / Non-Goals) and **dependencies** only — the *approach* is designed
> just-in-time when this moves to `design`. Do not pre-design it here.

## Context

STAGE-003's first spec and the one that settles the vocabulary everything else in the stage (and the writer stages after it) uses. `exif-core` can read TIFF and JPEG; nothing yet says what is *in* a file in privacy terms. This spec adds the pure-library audit model over what the readers already return.

Open questions it must settle at design: which tags and regions fall in which category (GPS, device identity and serials, authorship, timestamps, thumbnail, MakerNote presence, XMP/IPTC/ICC/JUMBF presence) and why, recorded in a DEC before code (DEC-008); how findings from **every** Exif block are reported (question `several-exif-segments`); how an unsupported or non-metadata file is represented so it never reads as clean.

## Goal

A pure function from bytes to a `FileAudit`: the sniffed container (or unsupported), the inventory (every tag with its IFD kind, id, type and count, and every located region), and PII findings by category, each pointing at where it was found. No I/O, no dependencies, no panics, tolerant like the readers it wraps.

## Non-Goals

- Strip policy presets or any preview (SPEC-014); rendering (SPEC-015); the binary (SPEC-016)
- Decoding XMP/ICC/IPTC/C2PA; parsing MakerNotes; recursing into an embedded thumbnail (question `audit-thumbnail-recursion`)
- PNG, WebP, HEIC
